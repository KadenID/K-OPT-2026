macOS · Apple Silicon(arm64) 사용자용 안내

K-OPT 2026 “손상되었기 때문에 열 수 없습니다” 오류 해결 매뉴얼

Apple Silicon용 K-OPT 2026 앱이 macOS에서 열리지 않을 때의 확인·해결 절차입니다. 기본 대상은 osx-arm64 배포본이며, Intel Mac의 차이점은 아래 주의사항에 따로 정리했습니다.

먼저 Mac 종류를 확인합니다. Apple 메뉴() → 이 Mac에 관하여에서 ‘칩’에 Apple M 시리즈가 표시되면 아래 ARM 절차를 따릅니다. ‘프로세서’에 Intel이 표시되면 Intel Mac 주의사항을 확인합니다.

1. 증상

압축을 풀고 K-OPT 2026 앱을 더블클릭하면 아래와 같은 경고창이 나타납니다.

‘휴지통으로 이동’은 누르지 마십시오. 반드시 ‘취소’를 눌러 창을 닫아 주십시오.

2. 원인

이 경고만으로 실제 파일 손상 여부를 단정할 수는 없습니다. 내려받은 파일의 격리 표시나 서명 상태 때문에 macOS 보안 기능(Gatekeeper)이 실행을 막는 경우에도 나타날 수 있습니다. 아래는 해당 배포본에서 확인할 항목입니다.

원인설명
격리(quarantine) 표시인터넷(메일, 브라우저)으로 받은 파일에는 macOS가 ‘인터넷에서 받은 파일’이라는 표시를 자동으로 붙입니다.
코드 서명 불일치앱을 묶는 과정에서 임시(ad-hoc) 서명과 번들 구성이 맞지 않으면 서명 검증에 실패할 수 있습니다.

3. 해결 절차

1압축 해제

다운로드 폴더에서 K-OPT_2026-osx-arm64-….tar.gz 파일을 더블클릭합니다. 압축을 푼 K-OPT_2026-osx-arm64-… 폴더 안에 K-OPT 2026.app이 있는지 확인합니다.

2터미널 열기

⌘ Command + Space를 눌러 Spotlight를 열고 터미널을 입력한 뒤 Enter를 누릅니다.

3명령 입력

아래 세 줄을 한꺼번에 복사하여 터미널에 붙여 넣고 Enter를 누릅니다. 각 줄 끝의 &&는 앞 단계가 성공한 경우에만 다음 명령을 실행하도록 연결합니다.

cd ~/Downloads/K-OPT_2026-osx-arm64-*/ &&
xattr -dr com.apple.quarantine "K-OPT 2026.app" &&
codesign --force --deep -s - "K-OPT 2026.app"
명령역할
cd ~/Downloads/K-OPT_2026-osx-arm64-*/압축을 푼 ARM용 K-OPT 폴더로 이동합니다. *는 버전·날짜 부분을 대신합니다. 일치하는 폴더가 하나일 때 사용합니다.
xattr -dr …앱과 그 안의 모든 파일에서 격리 표시를 제거합니다.
codesign --force …앱 번들 전체에 임시(ad-hoc) 서명을 다시 적용합니다. 개발자 신원 확인이나 Apple 공증을 대신하지는 않습니다.
앱을 다른 곳(예: 응용 프로그램 폴더)으로 옮겼다면 첫 줄을 cd /Applications &&처럼 실제 앱이 있는 위치로 바꿉니다. 다운로드 폴더에 ARM 배포본 폴더가 여러 개 있으면 * 대신 이번에 압축을 푼 폴더의 전체 이름을 입력합니다.

4결과 확인

서명이 교체되면 replacing existing signature라는 문구가 나올 수 있습니다. 아래 명령으로 서명 검증이 통과하는지 확인합니다.

codesign --verify --deep --strict "K-OPT 2026.app" && echo "서명 정상"

5앱 실행

압축을 푼 폴더에서 K-OPT 2026 앱을 더블클릭하여 실행합니다.

Apple Silicon용 osx-arm64 배포본은 기본적으로 Rosetta 설치 없이 실행합니다. Intel 앱 또는 Rosetta 관련 안내가 나타나면 아래 주의사항에서 내려받은 배포본 종류를 확인합니다.
주의 — Intel Mac에서 사용할 때만 바꿀 부분
  • 다운로드 파일은 ARM용이 아닌 K-OPT_2026-osx-x64-….tar.gz를 선택합니다. 파일 이름만 바꾸는 것이 아니라 실제 Intel용 배포본을 받아야 합니다.
  • 3단계 명령의 첫 줄에서 osx-arm64를 osx-x64로 바꿉니다. 즉, cd ~/Downloads/K-OPT_2026-osx-x64-*/ &&로 시작합니다.
  • 그 뒤의 격리 표시 제거·서명·검증·앱 실행 절차는 동일합니다. 앱 이름 K-OPT 2026.app은 바꾸지 않습니다.

Apple Silicon Mac에서 Intel용 파일을 잘못 받은 경우에는 Rosetta 설치를 기본 해결책으로 삼지 말고, osx-arm64 배포본을 다시 받아 1단계부터 진행합니다.

4. 자주 묻는 질문

Q. ‘No such file or directory’ 오류가 나옵니다.
앱의 위치·폴더 이름이 다르거나 압축을 풀지 않은 경우입니다. 1단계의 ARM 폴더와 앱 위치를 확인합니다. Finder에서 해당 폴더를 터미널로 끌어다 놓으면 실제 경로를 입력할 수 있습니다. cd 뒤에 이 경로를 넣고 나머지 명령을 진행합니다. ‘too many arguments’ 또는 ‘인수가 너무 많음’이 나오면 일치하는 폴더가 여러 개인지 확인하고 * 대신 정확한 폴더 이름을 사용합니다.

Q. 새 버전을 받을 때마다 다시 해야 합니까?
새로 내려받은 앱에서 같은 실행 오류가 발생하는 경우에만 이 절차를 다시 확인합니다. 새 배포본이 정상적으로 실행된다면 별도 조치는 필요하지 않습니다.

Q. 이 작업이 보안상 안전합니까?
이 절차는 지정한 앱의 격리 표시를 제거하고 임시 서명을 적용합니다. 개발자 신원이나 파일의 안전성을 보증하지 않으므로 신뢰할 수 있는 경로로 받은 파일에만 적용합니다.

5. 배포 담당자 참고 사항

  • 실행 파일만 임시 서명된 상태에서 번들을 조립하면 code has no resources but signature indicates they must be present 등의 검증 오류가 발생할 수 있습니다. 배포본마다 번들 전체의 서명 상태를 확인합니다.
  • 번들을 조립한 이후에 서명하고, 완성된 배포본에서 codesign --verify --deep --strict 검증을 진행합니다.
  • 사용자 조치 없이 실행되게 하려면 Apple Developer ID 서명과 공증(notarization)이 필요합니다.
  • 기본 배포 대상은 Apple Silicon용 osx-arm64로 구성하며, 포함된 네이티브 라이브러리도 ARM 아키텍처와 일치시킵니다.
